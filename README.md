# Project Description

This project analyzes generated fitness session data
of a participant generated by the data_generator.py.
the program validates sensor observations, compares heart rate
with the participants baseline, and classifies the session in 5 categories,
such as resting, moderate activity, high activity, recovering, or insufficient data.

the program uses the provided fitness data generator as mentioned above,
and converts the generated dictionaries into Python objects before
analyzing the complete session. 

# Class responsibilities

## ReferenceProfile()
stores the participants personal baseline measurements,
including baseline heart rate, skin response and temperature.

## Participant()
Represents a participant and stores the participant ID together
with their ReferenceProfile.

## Observation()
Represents one observation window from the fitness session.
It stores timestamp, heart rate, skin response, temperature,
activity level and signal quality.
It also validates observations and provides a class method for
creating an Observation object from a dictionary.

## FitnessSession()
Represents a complete fitness session. It contains a Participant
and collection of Observation objects. Observations are added to the session
using the def add_observation().

# OOP Design

## Composition
Composition is used to model "has-a" relationships in the program. 
A participant "has-a" ReferenceProfile, and a FitnessSession "has-a" Participant
and a collection of Observation Objects.

## Encapsulation
FitnessSession uses the protected style attribute. _observations to store its observations.
New observations are added using the "add_observation()" method, and the observations are
accessed through the "observations" property.


## Inheritance and Overriding
Inheritance and method overriding are not used in this project because the relationship
between the main classes are better represented using composition. a FitnessSession "has-a"
Participant and Observation obects, and a Participant "has-a" ReferenceProfile. Since these are 
"has-a" relationships, Inheritance which is a "is-a" relationship, would not improve the design.

## Classification Rules and Assumptions
The program uses these rules to classify a fitness session

"Insufficient data" if there are fewer than 4 valid observations are available.
"Recovering" if there are at least 4 valid observations, and both heart rate and activity level decreases
from the beginning to end of the session.
"Resting" if the average_activity is below 0.30 and average_heart_rate is less than 20 BPM above the participants baseline.
"Moderate activity" if the activity is below 0.68 and average_heart_rate is less that 50 BPM above the participants baseline.
"High activity" if the session does not meet neither of the activity listed above.

## Validation rules
An observation is considered valid when the following conditions are met:

heart rate > 35 and < 205 BPM
temperature > 25 and < 42 Degrees Celsius
activity level > 0 and < 1
signal quality > 0 and < 1
skin response >= 0
required measurements is not "None"

Invalid observations are excluded from the session calculations.

## Limitations
the classification are designed for the supplied fitness data generator
and may not be suitable for real world fitness data. 
Recovery detection is simplified and only checks whether the heart rate and activity level
decreases from the beginning to the end of the session. 
Lastly, the program analyzes generated data and is not intended for medical or health diagnosis.
